## 后续实现仍需满足的检查点

1. **三类接纳不能混用**：核心请求接纳、Session turn admission、provider acceptance。
   保留 OpenScience 现有会话准备与持久化顺序。
2. **冻结角色调用输入**：科研 TaskSnapshot 与改进/选择调用的 mission、system、证据包分开。
3. **缓存完整身份**：更换输入、模型、环境或配置后不能复用旧结果；输入文件后续修改不改变旧快照。
4. **控制停止穿透方法层**：取消、超时、预算耗尽不能被普通异常回退吞掉。
5. **预算按真实执行计数**：共享基线只记一次；包含提案重试、选择、反思和 Reviewer。
6. **保留证据边界**：沿用产物版本和 Review，独立评分不进入优化与经验上下文。
7. **升级可核对**：每轮列出新增上游差异，保留固定提交与许可证；先复用模块，再为已证实的接口缺口做最小改动。上游更新单独提交并运行方法等价与原功能回归。

## Git 与协同约定

- 每轮一个集成分支及 PR；子智能体只在各自 worktree/分支提交，由主智能体审查整合。
- 主智能体负责契约及集成结果，两个子智能体分别负责 OpenScience 与 Harness²。
- 核心开发使用用户指定的 `gpt-6.1-sol / high`；其他模型调整另行明确。
- 上游 Actions 保持关闭，先完成 EarthNano 专用验证流程的配置再启用。
- PR 中分别列出源码变更、真实执行的检查、未验证内容与后续任务；不自动合并。

第七轮的 `eligible` 仅表示有资格继续跨任务验证；实验生命周期 `completed`、产物验收和配置状态分别显示。
自动触发策略（例如一次常规修复后升级到优化）留待普通执行统一后实现，不能把环境故障或缺少可核验标准直接当作优化问题。
