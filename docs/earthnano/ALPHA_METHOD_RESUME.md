# Explicit settled experiment resume

The backend accepts `runPersistentOptimization({...originalOptions, resume: true})` with the original exclusive `workRoot`. `readPersistentOptimizationResume(workRoot)` returns the descriptor needed by the desktop owner to reconstruct and reauthorize those options. The public desktop action supplies only the original run key; it cannot supply replacement task data, criteria, model or budget. The original provider/runtime binding is checked again even when the whole result is cached.

The descriptor `resume.json` contains `schemaVersion: 1`, original `optimizationId`, full normalized `identity`, `identityDigest`, and `methodDigest`. The identity pins the project, source Session/message, task ID, complete task/agent/harness/environment including managed version tuples, input provenance, method parameters, criteria, deterministic checks, domain, admission budget and per-execution timeout. The method digest pins actual Python package source bytes. Generated Python cache files and the workspace location do not change that identity. No credentials are saved.

`request-tasks.json` is a checksummed routing index, mapping immutable request keys to the original task ID and role/stage/label/attempt slot. It provides routing for identical task bytes in different domain positions; it cannot authorize completion. Every reusable record must still pass the original journal request digest, terminal settlement, confirmed cleanup, original immutable snapshot resolution, exact original version export and passing integrity Reviews. The original Core owns admission, cancellation and the unchanged budget. Failed and cancelled admissions remain charged in the journal; explicit retries consume remaining budget and retain retry lineage.

The original `schedule.run_task`, `_resume`, runmark harness fingerprints, sequential/parallel recursion, final selector, `run_domain`, reflection and Library restoration remain in use. The single narrow scheduler change enables its existing `_resume` branch for an explicitly resumed port execution. Local result projections persist external original runmarks and verified version metadata. Restoring a partial stage regenerates its original frozen request; Core returns its existing execution handle without dispatch or admission. Original complete task summaries restore through `_resume` and retain the original `skipped` summary status. The API reports these successfully restored tasks as `ok`.

Independent semantic assessments freeze their evidence again, including the bounded original source manifest when applicable. Only an exact completed reviewer request may be substituted before the evaluator's unchanged request-digest checks. Original semantic/deterministic Review owners reuse exact matching Reviews; completing and reopening an experiment therefore preserves Review IDs.

A changed identity, changed scheduler source, malformed routing metadata, altered snapshot, missing or changed original output, failed integrity Review, live lock, or unknown cleanup fails closed before another paid dispatch. Pre-Alpha runs without the descriptor are not resumable through this action. Process-restarted/unknown resources require the original physical reconciliation path; this action does not reclaim their locks or treat source retention as successful resume. This batch does not claim complete product integration of that separate reconciliation workflow.

Validation uses the pinned Harness² baseline in `UPSTREAMS.json` (`1cfe254e8d25b15f37048c3730134686abe60335`). The original Python tests and existing native Session/Core integration remain applicable. New tests cover partial sequential/parallel continuation, complete domain/Library restoration, immutable projection tampering, exact cache identity, unknown settlement refusal, and a real local native-CLI run that stops partway, completes only remaining stages and reopens with zero model requests and unchanged execution/Review IDs. The local HTTP fixture rejects only the unchanged native CLI's optional `HEAD /api/hello` health probes; no paid endpoint is used.

## Explicit unknown-resource audit

`reconcilePersistentOptimization({workRoot, projectId, sourceSessionId, authorize, signal})` is a host-only backend action. The caller holds the original data-root lifetime writer lease and supplies current source authorization. It accepts no replacement task, outcome, resource identifier, budget or model request from the renderer. The result separates `status: settled|fenced` from `resumeAllowed` and returns only execution IDs, phases, cleanup facts and bounded reason codes.

The fixed OpenScience baseline (`9e18c7d3c143a9dba49c7a586ad6cac8096f6dd5`) keeps ACP `ChildProcess`, epoch and lease ownership in `AcpConnectionResourceOwner` memory. Its `TaskRunner.restoreRuns` repairs durable Task/Session interruption projections; that is not proof that an ACP process tree was reaped. The original Notebook kernel/shell receipts can prove their own subresources, but cannot substitute for missing ACP ownership. These boundaries are retained.

New executions can close one real crash window. Only after the original candidate owner acknowledges both `AcpRuntimeCoordinator.shutdownForQuit()` with `reaped: true` and shutdown of its owned Notebook lane, the driver writes an immutable `owner-settlements/<executionId>.json` receipt before returning its terminal outcome to Core. This receipt binds the complete request digest, exact original execution/Session identity, outcome and resource scope. It does not claim the shared application Notebook RPC server was stopped. Receipt persistence failure leaves Core cleanup unknown. The receipt uses the same host-owned private storage boundary as the original execution journal; its checksum detects corruption and identity mismatches, not an independent cryptographic authority.

The explicit audit validates the manifest scope, original budget and journal records, then requires a matching valid receipt for every unresolved record **before** attempting the original verified-dead writer recovery. The original Core records cleanup confirmation with receipt evidence; existing phase, error, usage, effective configuration, output evidence and charged budget are preserved. Repeating the audit does not duplicate evidence or dispatch anything. Live, inaccessible or malformed writer ownership remains fenced. Already confirmed original journal state may retire a verified-dead leftover writer lock through the same original store owner.

Interrupted history is not promoted to completed. If a late receipt says work completed while the journal retains a failure, the runner refuses paid replay with `historical-result-not-adopted`; adopting that result requires a separate original result-owner path. A successful resource audit therefore does not promise the experiment is resumable. Crashes before physical retirement or before durable receipt persistence, and old unknown executions without receipts, remain fenced. General cold ACP recovery still needs original owner-created process birth/group/descendant receipts and lease/capability retirement evidence before spawn, followed by original process-tree verification; neither a missing status file nor a dead application PID supplies those facts.

Meaningful validation includes original driver shutdown ordering, no receipt on early/failed teardown, durable-write failure fencing, mismatched/corrupt/duplicate receipts, original error/budget preservation, and an isolated real writer process that retires a real child through the original process-tree owner, durably writes its receipt, then exits before Core's terminal commit. The restarted audit confirms only cleanup and preserves interruption without model replay. No paid provider is used.

The Alpha Notebook parallel resume regression exposed an EarthNano private adapter issue: initial method config preserved object-key insertion order, while the durable resume projection sorted JSON keys. Re-rendering managed-input metadata from those objects changed the source evidence bytes despite identical version tuples, so strict invocation matching correctly rejected the completed proposer. The adapter now serializes that metadata with sorted object keys from its first creation. Array order and all tuple/version/digest fields remain significant. This changes the pinned method source digest; existing manifests remain intact and refuse continuation across that implementation version rather than silently replaying paid work. It does not modify the upstream schedule or relax any immutable reference comparison.
