# Explicit settled experiment resume

The backend accepts `runPersistentOptimization({...originalOptions, resume: true})` with the original exclusive `workRoot`. `readPersistentOptimizationResume(workRoot)` returns the descriptor needed by the desktop owner to reconstruct and reauthorize those options. The public desktop action supplies only the original run key; it cannot supply replacement task data, criteria, model or budget. The original provider/runtime binding is checked again even when the whole result is cached.

The descriptor `resume.json` contains `schemaVersion: 1`, original `optimizationId`, full normalized `identity`, `identityDigest`, and `methodDigest`. The identity pins the project, source Session/message, task ID, complete task/agent/harness/environment including managed version tuples, input provenance, method parameters, criteria, deterministic checks, domain, admission budget and per-execution timeout. The method digest pins actual Python package source bytes. Generated Python cache files and the workspace location do not change that identity. No credentials are saved.

`request-tasks.json` is a checksummed routing index, mapping immutable request keys to the original task ID and role/stage/label/attempt slot. It provides routing for identical task bytes in different domain positions; it cannot authorize completion. Every reusable record must still pass the original journal request digest, terminal settlement, confirmed cleanup, original immutable snapshot resolution, exact original version export and passing integrity Reviews. The original Core owns admission, cancellation and the unchanged budget. Failed and cancelled admissions remain charged in the journal; explicit retries consume remaining budget and retain retry lineage.

The original `schedule.run_task`, `_resume`, runmark harness fingerprints, sequential/parallel recursion, final selector, `run_domain`, reflection and Library restoration remain in use. The single narrow scheduler change enables its existing `_resume` branch for an explicitly resumed port execution. Local result projections persist external original runmarks and verified version metadata. Restoring a partial stage regenerates its original frozen request; Core returns its existing execution handle without dispatch or admission. Original complete task summaries restore through `_resume` and retain the original `skipped` summary status. The API reports these successfully restored tasks as `ok`.

Independent semantic assessments freeze their evidence again, including the bounded original source manifest when applicable. Only an exact completed reviewer request may be substituted before the evaluator's unchanged request-digest checks. Original semantic/deterministic Review owners reuse exact matching Reviews; completing and reopening an experiment therefore preserves Review IDs.

A changed identity, changed scheduler source, malformed routing metadata, altered snapshot, missing or changed original output, failed integrity Review, live lock, or unknown cleanup fails closed before another paid dispatch. Pre-Alpha runs without the descriptor are not resumable through this action. Process-restarted/unknown resources require the original physical reconciliation path; this action does not reclaim their locks or treat source retention as successful resume. This batch does not claim complete product integration of that separate reconciliation workflow.

Validation uses the pinned Harness² baseline in `UPSTREAMS.json` (`1cfe254e8d25b15f37048c3730134686abe60335`). The original Python tests and existing native Session/Core integration remain applicable. New tests cover partial sequential/parallel continuation, complete domain/Library restoration, immutable projection tampering, exact cache identity, unknown settlement refusal, and a real local native-CLI run that stops partway, completes only remaining stages and reopens with zero model requests and unchanged execution/Review IDs. The local HTTP fixture rejects only the unchanged native CLI's optional `HEAD /api/hello` health probes; no paid endpoint is used.
