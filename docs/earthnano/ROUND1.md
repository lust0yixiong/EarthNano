## 审查结论与已纳入契约的修订

两侧存在可抽取的执行边界，但现有接口和生命周期并不等价。深度融合应共享运行事实、
输入配置和证据规则，同时保留 OpenScience 的既有状态所有者及 Harness² 的方法语义。
这些结论支持下一轮实现共享契约，不代表两个项目现在已经能够直接对接。

| 审查发现 | 契约中的处理 | 后续实现位置 |
| --- | --- | --- |
| 任务内容不足以定义 proposer、selector 等角色调用 | 增加冻结的 invocationRef，包含阶段提示、可见证据和 Library 快照 | 核心输入与 Harness² 调用构造 |
| 桌面接纳、任务 API 准备会话与 provider 执行边界不同 | 分开核心接纳、Session admission、provider acceptance，保持原有 façade 返回语义 | ACP 与 task-agent-port |
| OpenScience 已有多种执行/轮次身份和状态 owner | 新核心身份显式关联既有 run/session/attempt/runtime/turnToken，不覆盖原标识 | 核心映射与事件采集 |
| Harness² solver 与改进角色有两条执行路径 | adapter.execute 和 Proposer.call 均进入共同端口，重试有独立身份 | spec、recursion、proposer |
| 上游部分缓存未包含任务或模型身份 | 缓存需匹配完整请求、物化配置及有效证据；与提交去重分开 | 核心复用与方法恢复 |
| 普通错误回退可能吞掉平台停止信号 | 取消、超时、预算停止穿透方法层；清理未知保留隔离栅栏 | 方法控制与运行清理 |
| 生成配置不代表后端已加载；旧模型/effort 存在回退 | 新候选严格校验，普通入口保留兼容；生效状态允许 unknown | 后端配置编译与回执 |
| ArtifactVersion、Reviewer 已有权威数据 | 复用版本和评估引用，保持 autoReview 等待语义；独立评测不回流优化 | 产物/审阅与证据服务 |
| 方法 R/P 并非真实费用账本 | 共享基线只记一次，重试/selector/reflection 另计；未知用量不写零 | 预算准入与用量采集 |
| 选择成功不证明比基线更好，Library 也不是全局默认配置 | 保留 finals/k=1 规则、严格历史前缀及 NO_ENTRY；采用与质量结论另记 | 选择、经验与后续采用 |

两份独立审查保留初稿意见和源码行号；上表表示已修订文档中的要求，
不表示已修复上游缓存、权限、取消、配置加载或费用采集。
