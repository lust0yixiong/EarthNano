# 第七轮：原生领域任务流、实验内经验与分离验收

本轮延续深度融合：科研工作区、持久化和执行事实由同一平台管理，优化过程复用原 Harness²。
未引入第二套运行数据库或外接调度服务。基线是 PR #8 的 `d9db3c785`；PR #8 仍开放，
本轮以它的分支 `feat/round6-harness-recursion` 为合并目标，不自动合并。

## 实现和调用关系

桌面 `TaskOptimizationPanel` → 原 typed command / IPC → `DesktopOptimizationManager`
→ `runPersistentOptimization` → 同一个 `ExecutionCore`、Claude Code/ACP driver 和
Session / ArtifactVersion / Review owners。领域模式的 Python 调用仍通过原 JSONL seam 回到这个核心。

| 模块 | 本轮处理 |
| --- | --- |
| `schedule.task_stream/run_domain` | 直接调用原实现，按声明顺序执行本次实验的任务 |
| `recursion`、`proposal`、`selection` | 保留原递归、生成、组合、匿名选择与失败行为，本轮不修改这些核心模块 |
| `selection.reflect_adoption`、`library.Library` | 复用原反思、经验解析、索引和后续任务上下文；不重写经验算法 |
| `earthnano_domain.py` | 新增显式领域入口，逐任务绑定平台请求和输出，原 `earthnano.py` 单任务入口不变 |
| `HarnessDomainBinding` | 将任务 ID、请求和 execution ID 关联到原每任务 binding，统一预算和停止，不以相同快照引用猜测归属 |
| `domain-results` | 核对原 Library 投影与选中配置、反思 Session、固定 ArtifactVersion 的归属、校验和及经验字段 |
| `research-verification`、`output-checks` | 在独立语义评审之后检查所选固定产物；期望值、JSON pointer、容差先冻结 |
| 原 Review owner | 将确定性检查写为原 scoped Review，使用原提交、错误和证据机制 |
| 桌面任务面板、共享类型、IPC | 增加可选领域任务和 JSON 检查，逐项显示结果、经验来源与审阅链接，保留单任务调用 |

两个开发子智能体继续使用指定的 `gpt-6.1-sol / high`，分别负责平台与方法入口。
主智能体先落共同契约、类型与边界，再整合执行路径；随后进行交叉审查和持久化边界测试。
详见 [最小契约](ROUND7_CONTRACT.md) 和 [原方法入口说明](../../vendor/harness2/EARTHNANO_DOMAIN.md)。

## 用户能力与结果含义

用户仍可显式启动单任务优化。可选的领域实验包含当前任务及最多三个后续任务，
共享同一 method、base harness、执行预算、停止操作和总时限。桌面新增任务复制当前输入文件；
内部 typed API 支持每个任务各自冻结输入，真实集成验证使用不同 CSV，核对任务归属。

预算按执行次数计数，涵盖基线、改进、组合、候选、选择、反思、独立评审和重试。
确定性检查本身不调用模型。1–4 个任务、k=1–8、平台上限 128 次的组合须满足预算；
本轮没有货币预算控制。普通 Send、文献和原科研能力的入口保持原调用路径；尚未迁移到共同核心。

三个状态分别保存和显示：

- **运行生命周期**：是否执行完毕并确认清理；`completed` 不代表科研结论正确。
- **产物验收**：独立语义评审和已提供的确定性检查是否通过；模型单独判为通过仍是 `unverified`。
- **配置资格**：产物失败或模型分数退步时阻止；通过仅表示有资格继续跨任务验证，不代表发布。

领域实验仅显示逐任务结论，不将首个任务的状态投射为总体结论。
停止发生在方法阶段时保留声明顺序及原执行证据，不伪造尚未核验的经验索引；
在后续评审阶段停止时，保留先前任务已完成的结果。
确定性 Review 发生迟到取消或提交失败时转为 error/null outcome，不保留通过结论。

JSON 检查是有限的文件路径 / JSON pointer / 期望值等值或数值容差检查，不执行模型生成的代码。
它核对指定结果文件，不能替代科研方法、输入数据质量或领域正确性的验证。

## 原经验机制与独立评估边界

原 Harness² 先反思并写入 Library，后续任务可读取该原始经验；独立评估在整个方法流结束后进行。
保留这一顺序以便核对上游方法等价性。因此，这是一份**本次实验内的原始经验**，
可能包含后来验收未通过的配置或结论，不是已验证的共享知识库。

Library 投影必须关联本次实验的选中 harness、反思 execution 和固定 ArtifactVersions；
拒绝跨任务归属、混合 mode、额外路径、大小写别名、被篡改经验和版本校验失败。
原 Session owner 将与方法读取的同一份审阅投影保存为 `reflection-reply.md`，
通过原 Artifact owner 生成版本并核对发布前后回复字节。保留模型自行写出的文件；
拒绝模型占用保留文件名，包含派生产物在内仍满足 64 文件 / 4 MiB 输出上限。
原 `NO_ENTRY`、不完整反思或普通失败按原方法处理，不制造经验。
独立 criteria、期望输出、Review 结论和独立分数保存在私有 assessment plan / Review，
不进入方法上下文或 Library。没有自动发布配置、跨实验导入经验或隐藏的评分反馈优化。

## 验证与限制

最终 DeepSeek 联调通过：23 次执行、23 个 Session、两个任务独立验收通过，固定版本和 Review 可重开。
保留一次原 `dom1` 回退及额外付费尝试。两个产物都通过验收，第二个配置因模型评审分数
从基线 100 降至 95 被标记为 blocked，没有发布。首个任务为 `NO_ENTRY`，第二个任务增加 1 条经验，
因此本次真实模型没有覆盖向后续任务传递经验；该路径由离线真实原生进程和原方法等价测试证明。
四次 API 诊断尝试全部记录；前一次修复生产持久化问题，后两次修正夹具对上游行为的过度假设。

可复核结果见 [离线验证记录](ROUND7_VALIDATION.json) 和 [DeepSeek 联调记录](ROUND7_DEEPSEEK_VALIDATION.json)。
测试区分原算法等价性、共享边界、真实原生进程/SQLite 和浏览器夹具；不会把 mock 成功当作真实模型证明。
DeepSeek 使用原 Claude Code/ACP 与 Anthropic 兼容接口，授权密钥只在本地测试观察器内读取。

验证修复包括：拒绝将数组 `length` 当作 JSON 成员、逐任务展示配置状态、预先冻结检查目标，
以及保留停止时的领域投影。首次真实模型调用发现模型另写的经验文件与回复不一致，
严格门禁阻止后续验收；改由原 owner 保存相同回复投影，未改动原经验解析或降低核对要求。一次加强经验传递断言时，夹具没有计入已有 backtick JSON 转义，
导致断言失败；修正断言后核对相同原始 Library 内容，未放宽生产验收条件。
真实模型夹具还移除了“每个任务必须生成经验”和“每次必须改变配置且不回退”的假设：
原方法允许 `NO_ENTRY` 和回退，联调须如实记录这些结果。确定性与语义验收、版本核对和共同预算门禁不变。
