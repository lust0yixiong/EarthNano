# EarthNano

## 已确定的方向

- 桌面应用优先，先面向地学与遥感科研人员，随后扩展到通用科研。
- 保留 OpenScience 现有用户能力，吸收 Harness² 的优化机制，允许大幅重构内部架构。
- 配置优化由系统自动触发，普通执行与优化执行共用运行基础设施。
- 基于两个开源项目演进，不预设用户必须执行某一种科研流程。

[最小任务清单](NEXT_TASKS.md)，共同边界见 [最小核心契约](CORE_CONTRACT.md)。

## 四个工作包

### 1. 验证开发基线

启动 OpenScience，执行适用的现有测试，记录原有失败与环境条件。

验收：应用可启动，核心科研操作可用，有可重复执行的回归检查。

### 2. 统一执行与配置加载

从 OpenScience 的 ACP 运行体系提供内部执行入口，让 Harness² 的任务执行
（`adapter.execute`）与改进执行（`Proposer.call`）共同使用。
每次候选使用明确的配置版本、独立工作目录和可追溯的轨迹与产物。

验收：先在一个后端证明配置实际生效、候选互不干扰、执行可取消、结果可追溯；
OpenScience 原有桌面和任务 API 行为保持兼容。

### 3. 接入自动优化闭环

保留 Harness² 的生成、试跑、组合、选择和经验整理方法，在证据保存完成后自动调度。
统一预算、停止与恢复，区分普通执行和优化内部执行，防止递归触发。

验收：普通桌面任务可自动进入优化；所有模型调用受共同管理；
预算不足不启动下一阶段，重启不重复提交已完成阶段。

### 4. 完成融合与发布准备

合并重复的配置存储、运行日志和恢复记录，复用 OpenScience 产物版本、Reviewer 与复现能力；
扩展后端支持，完成桌面打包和原有功能回归。

验收：形成可供用户使用的 EarthNano，能够说明优化是否有效及其时间、费用代价。

## 开发方式

- `main` 保存可追溯的基线与经过验证的改动。
- 每个工作包使用功能分支，通过 PR 描述变更、验证结果和限制。
- 多智能体开发时使用各自的分支和 worktree，由主智能体整合。
- 先确定最小核心契约并落实共享类型与契约测试，再并行修改执行模块和优化模块。
- `vendor/harness2/` 已包含共享契约和方法执行 seam 的集成改动。后续修改或抽取必须在 PR 中说明，
  并更新来源记录中的集成状态，避免将改动后的目录误认为原始源码。
- 上游更新单独进行，固定提交后验证，不将上游更新与功能融合混在同一批改动中。
