# EarthNano 实施计划

## 方向与范围

- 基于 OpenScience 和 Harness² 深度融合，不预设用户必须属于某一学科或执行某一种科研流程。
- 保留 OpenScience 现有用户能力，复用 Harness² 的核心方法，允许重构内部架构。
- 普通执行、优化基线和候选使用同一任务、配置、运行、产物与审阅事实体系，不各建一套规则。
- 优先复用上游模块；先对照原源码与原测试定位故障，再做最小必要修复。
- 产品和应用名为 EarthNano；保留上游许可、历史和数据/凭据/CLI/MCP/协议等兼容标识。

来源分类见 [FUNCTION_ORIGINS.md](FUNCTION_ORIGINS.md)。自动触发、平台配置审批发布/回滚与完整精确费用账本是新增设计，单独跟踪；不把它们尚未实现称为上游能力丢失，也不据此无限扩展 Alpha。

## 已实现及待验收的边界

`main` 已合并 PR #1–12。普通 Send、Task、Reviewer、委派与优化进入共同 ExecutionCore；Notebook Python 基线与候选重新执行同一科研任务。原递归、提案/组合、匿名选择、Library/反思已有集成证据。

PR #13–17 为尚待审查/CI 的 Alpha 依赖链：显式续跑、白底图标、原用量接线、完整 sweep、桌面多来源 catalog 与 R。R 在固定生产/E2E 提交取得真实原 kernel、Session/产物/Review、离线桌面和 DeepSeek 证据，见 [R 验收](ALPHA_R_CONTRACT.md)。这些分项通过不等于完整 Alpha 或跨平台发布通过。

固定上游及集成改动见 [UPSTREAMS.json](../../UPSTREAMS.json)。`vendor/harness2/` 包含融合改动，不能当成未修改原树；原方法等价性以固定原树对照为准。当前运行状态以具体 PR、job 和原始报告为准，历史账户限制不作为新的阻断理由。

## 剩余实施顺序

1. **收敛已有 PR 和回归。** 将已证实的修复纳入明确提交，用相同环境对照固定上游，处理新增失败、缺失报告与实际构建问题。收集任务成功不等于原测试全部通过。
2. **完成原工具的候选融合。** 沿同一核心接通剩余 Compute、二进制等工具/数据表面，复用原授权、producer、版本与 Review。保留原完整 sweep、续跑及经验传递，不另写优化算法或科研运行时。
3. **整体验收并交付。** 同一科研任务由基线和候选执行，验证真实输入/产物、独立评估、预算/停止/续跑；用 DeepSeek 做有界验证，明确效果与用量限制。完成适用跨平台回归、原生包/白底图标观察、数据兼容和 Alpha 分发说明。

每项结果必须绑定实际提交、源码/运行时身份、执行命令和原始证据。科学结果合格、配置收益、运行成功与方法选择分别报告，不用单次模型评分证明普遍改进。

## 开发与交付方式

- 主智能体负责共同契约、集成与审阅；平台和方法子智能体分别在独立 worktree/分支工作，不自行定义另一套 DTO、状态或结果库。
- 共享类型/契约先通过，再并行接线；优先使用原 owner 和算法，跨边界修改先对齐接口。
- 通过 PR 提交，经适用检查及审查后合并；上游升级单独进行，不混入本轮融合。
- EarthNano 专用 CI 保留原测试和资源门槛；继承的发布、签名和定时工作流继续隔离，不能操作上游渠道。

当前工作队列见 [NEXT_TASKS.md](NEXT_TASKS.md)，版本完成标准见 [ALPHA_CONTRACT.md](ALPHA_CONTRACT.md)，源码试用见 [BASELINE.md](BASELINE.md)。第一至第十轮的过程与失败记录保留在各轮文档，不作为最新状态快照。
